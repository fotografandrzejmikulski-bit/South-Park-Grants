# Submission Checklist

## Repository

- [x] Public repository exists
- [x] README explains the thesis and research stage
- [x] Claims are separated into established evidence, hypotheses, and targets
- [x] Reference implementation exists
- [x] Unit tests exist
- [x] CI workflow exists
- [x] Reproducibility requirements documented
- [x] Experiment and configuration structure documented
- [ ] Add measured benchmark results once runs are executed
- [ ] Add hardware/model/checkpoint identifiers for every reported result

## Application

- [x] Founder identity and contact details
- [x] Clear problem statement
- [x] Narrow research hypothesis
- [x] Initial vertical slice
- [x] Evaluation criteria
- [x] Commercialization hypothesis
- [x] SPC-specific fit
- [x] Capital-use logic
- [x] 90-day plan
- [x] Risks and mitigations
- [x] No unsupported performance claims

## Evidence standard

Do not describe an experiment as validated until the repository contains the configuration, implementation, evaluation output, and enough metadata to reproduce it.

Do not describe target latency, cost reduction, safety efficacy, or feature stability as achieved performance unless a committed benchmark demonstrates it.
